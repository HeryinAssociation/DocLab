# Doclab AI 核校实施方案

依据 2026-10-15 本仓库源码与本机离线验证编写。目标是让 AI 代替重复核对，自动应用有原书依据的改动，将无法判定的少数问题留给人。

## 可以直接利用的现有能力

不必重做索引引擎：`core/tocio.py` 已提供 AI JSON 往返入口，`core/fixplan.py` 已有带证据的修订单，`core/manual.py` 已保存持久人工覆盖。AI 负责语义与证据判断，Doclab 负责落实修改和重算。

目录通道为 `toc-export → grep 取证 → 改 JSON 副本 → toc-import 演练 → 应用 → 再导出复核`。页码通道为 `读取校准观测／原页 → anchor 修订单 → fix 演练 → 应用并重算 → 复核整个受影响区间`。两者不能混为一次目录 JSON 导回。

MCP 已有 16 工具，但没有 `audit`、`fix` 或原页图像工具。当前推荐 MCP 配合本地 CLI；无命令行权限的客户端只能完成现有 MCP 支持的部分，并输出待执行页码修订单。

## 核校闭环

1. 用 `sources/status` 明确 source_id、PDF／EPUB、分片路径与已有阶段。保留当前 `manual_edits.json`、索引、校准、导出及对应摘要，记录人工层原本是否不存在。不要重跑 OCR 或用强制 adopt 重新登记已有书籍。
2. 没有校准或目录时，按 `pagecal → outline` 构建。已有人工结果先保存，再判断是否需要重算；不默认重建一切。
3. 指定核对深度，默认 L3，保留 `depth_limit`。逐节点检查同父层编号、层级模式、目录对照和正文起点；用 `audit` 作为补充线索，不把其 findings 直接等同于修正结论。
4. 漏标题必须在真实正文找到 `gid`；同名标题按父章、页位置和上下文区分。正文跨块、搜索截断时读取完整原始块。无法从正文确认的目录补全节点标为“仅目录定位”，不当作已视觉核实。
5. 生成目录 JSON 副本，对每个修改附 `reason`；删除条目的理由放顶层 `reasons[key]`，顶层 `note` 说明整体依据。普通标题不直接改字，不用重排数组模拟移动节点，不改页码字段期待写回。
6. 对 PDF 比对页码观测、前置／正文分段、页眉冲突、gap 与跨片接续。`anchor` 是向后区间覆盖，必须验证锚点到下一锚点或分片末尾的影响；发现未知插页、缺页或重编号而无法表达真实范围时不应用，留下明确问题。EPUB 保持 section_only，不从外文版边码构造本书页码。
7. 分别演练目录与页码变更，逐项比对意图及警告。应用前重读人工层和目录并比较内容摘要，变化则重算差异；当前没有服务器端版本锁或事务保证，需要避免与人同时编辑。
8. 页码先应用，再重新读取目录计算后续改动，避免拿旧目录 JSON 覆盖最新结构。检查应用返回值、失败项与重算结果。运行时可能部分失败，先查已生效项，再决定恢复，不能盲目重放。
9. 修改后导出指定深度并立即 verify；导出会同时装订 EPUB，需确认 `epub.verify.ok`，但 EPUB 结构自检不替代正文覆盖检查。读取导出首尾、同页多个小节边界及注释密集位置，核实全书原始内容块到输出文件的覆盖；不能仅凭现有 G2 通过便宣称全书无损。
10. 报告本次处理的深度／节点数／实际原页覆盖、改动、未决项、验证结果和恢复位置。将建议、已写入与已核验分开；warn 不改名为 pass。

## 对接后建议补齐的最小能力

以下是建议，当前没有修改程序来实现。

| 优先项 | 实施方式 | 原因 |
| --- | --- | --- |
| MCP 暴露 audit 与 fix | 继续薄封装现有 CLI，不复制算法 | 远程客户端能够完成页码修正和机械核查 |
| 读取完整原块及页码观测 | 返回 gid、shard、0 基 page_idx、全文、原页来源 | 现有 grep 限 400 字并过滤版面噪声，不足以独立复核页码 |
| 原页图像读取 | 由真实 PDF 与分片位置生成可查看的页面 | 验证 OCR 错字、页码和视觉层级 |
| 版本前置条件与批量提交 | 用人工层／索引内容摘要校验旧值，执行前完整验证动作 | 防止并发覆盖及运行时部分写入 |
| 全书块覆盖检查 | 对比全部应保留原块与所有导出区间，单独说明脚注／噪声规则 | 当前 G2 只核对已登记输出块，可能漏掉从未进入导出的内容 |

当前 `fixplan.validate` 检查 evidence 非空，不验证证据真假；`toc-import` 还能生成通用默认理由。因此 skill 仍必须自行提供具体位置及原文依据，不能把“接口接收”当作证据已核实。

## 样书验收

先在一本 PDF 副本上验证，再覆盖复杂分片 PDF 与 EPUB。用例需包括目录与正文简称差异、跨块标题、同页多个小节、前置页重编号、插页／缺页、跨片接续和 EPUB 外文版边码。

验收应看：误判与漏项是否改善、每个修正是否可追溯、原书内容是否完整覆盖、持久修正能否跨重算保留，以及重复运行是否不产生结构漂移。保留第一轮结果，再用同一书籍进行第二轮检查；不能凭幂等写接口推断 AI 判断也幂等。

本次仅完成源码核实、文档与 skill 编写，以及已有目录／修订单回归检查，没有真实书籍端到端验收。skill 在项目的 `skills/doclab-proofread` 中交付，未全局安装；支持加载本地技能的客户端可使用该目录，安装位置依客户端而定。

## 2026-11-17 内置 AI 目录核校（已实现，与 MCP 并存）

工作台新增 `ai-review`：用户在源详情页填 OpenAI 兼容的 `base_url` / `model` / token，点“AI 一键核校”先出预览，确认后应用。token 只写 `.env.local` 的 `DOCLAB_AI_TOKEN`，不写日志、不进报告；base/model 写 `config.json` 的 `ai` 段。

证据包只带目录平铺节点、与目录/编号/结构相关的 audit findings、正文取证窗口、页码观测与 `page_number`/`header` 原文字符，不读原页图。模型输出必须通过 key/gid/标题原文/evidence 校验；目录改动走 `tocio`，页码锚点走 `fixplan`，应用前备份、应用后重算并重跑 audit。页码只允许字符/序列推断：同页原文（含 O/0、l/1 混淆）或同分片相邻观测连续序列；无依据的进 `unresolved`，不新造锚点。

外部 AI 的 MCP 通道（`review_read` / `review_apply`）与 DSH 入库流程未改；内置 AI 只是同一人工核定层的另一个客户端。若同一本书有进行中的入库任务，内置 AI 应用后 revision 会变化，外部流程需重新读取目录。离线测试 `tests/test_ai_review.py` 18 项通过；真实实验使用 DeepSeek 兼容端点，只做预览，未应用真实改动。
